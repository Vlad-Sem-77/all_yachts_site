# Подготовка ALL-YACHTS.RU к размещению на VDS

Целевая конфигурация: Node.js 24, VDS с 2 CPU / 2 ГБ ОЗУ / 40 ГБ NVMe, отдельный PostgreSQL 16 в приватной сети и S3-совместимое хранилище. Compose запускает веб-сайт, API и обратный прокси; базу данных он не создаёт.

## Сервисы

- `web` — SSR-сайт на Express/EJS, порт 3000.
- `api` — API и Clerk Frontend API proxy, порт 5000; маршрут `/api/*`.
- `proxy` — Caddy, HTTPS для домена и маршрутизация `/api/*` в API-сервис.
- PostgreSQL и S3 предоставляются отдельно хостингом.

Оба приложения используют одну базу. Отдельный API-сервис необходим: он обслуживает `/api/*` и Clerk proxy, а веб-приложение отвечает за страницы, объявления, форум и загрузку фотографий.

## Подготовка перед запуском

1. Создать пустой кластер PostgreSQL 16 и получить приватную строку подключения. Применить к нему сетевые ограничения хостера.
2. Создать S3 bucket и ключ доступа с разрешениями только на чтение, запись и удаление объектов в этом bucket.
3. Настроить CORS bucket: разрешить `PUT` с `https://<ваш-домен>`, заголовки `Content-Type` и `*`, методы `PUT` и `HEAD`. Если провайдер требует `OPTIONS`, разрешить и его.
4. Настроить домен: DNS-запись `A` на публичный IP VDS; открыть входящие порты 80 и 443. Caddy автоматически запросит и продлит сертификат сайта.
5. Создать локальный `.env` из `.env.example` и заполнить его значениями из панелей хостинга. Не загружать `.env` в Git и не отправлять значения секретов в чат.
6. Указать рабочие production-ключи Clerk и проверить, что домен разрешён в соответствующей Clerk-конфигурации. Публичный ключ попадает в браузерную сборку; секретный ключ передаётся только серверным процессам.

## Первая установка

Все команды запускаются из корня репозитория на машине с Docker Compose:

```sh
cp .env.example .env
# Заполнить .env значениями хостинга
docker compose build
docker compose --profile maintenance run --rm migrate
docker compose up -d
docker compose ps
```

`migrate` применяет версионированные Drizzle-миграции: схему, начальное дерево категорий и разделы форума. Он предназначен для новой пустой базы. Не запускайте его поверх восстановленной базы с данными, пока не выбран и не проверен план переноса схемы и данных.

Для обновления кода:

```sh
docker compose build
docker compose --profile maintenance run --rm migrate
docker compose up -d
```

Перед запуском миграции на базе с важными данными проверьте резервную копию. Команда `pnpm --filter @workspace/db run push` предназначена для разработки и не является способом обновлять схему production-базы.

## Переменные окружения

Обязательны:

- `DATABASE_URL` — строка подключения к PostgreSQL 16 из панели хостинга.
- `SITE_HOST`, `SITE_URL` — один и тот же домен, в `SITE_URL` с `https://`.
- `SESSION_SECRET`, `ADMIN_USERNAME`, `ADMIN_PASSWORD` — отдельные значения для production.
- `CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY` — production-ключи Clerk для сайта.
- `S3_ENDPOINT_URL`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`.

`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` и `SMTP_FROM` необязательны. Без SMTP объявления и сайт работают, но письма не отправляются.

Для подключения PostgreSQL по TLS используйте параметры из точной строки подключения хостера. В его ответе TLS для базы требует публичный IP за 200 ₽/мес.; уточните у провайдера, требуется ли это для приватного соединения в выбранном кластере. TLS сайта на VDS обслуживает Caddy отдельно.

## Фото и перенос существующих данных

Сайт сохраняет в БД пути вида `/objects/listings/...`; в S3 они преобразуются в ключи с префиксом `S3_PREFIX`. Поэтому путь в БД не меняется. Загрузки идут браузером напрямую на временный S3 PUT URL, затем сервер проверяет размер, удаляет EXIF и сохраняет WebP-оригинал и миниатюру.

Текущие объекты Replit Object Storage автоматически в новый bucket не копируются. Если переносится база с уже опубликованными объявлениями, сначала скопируйте соответствующие объекты в S3, сохранив относительные пути, и только после проверки переключайте приложение на S3. S3 endpoint должен быть доступен из браузеров посетителей, а CORS — разрешать загрузку с домена сайта. Резервная копия PostgreSQL не содержит байты фотографий.

## Clerk и готовность к публикации

В Replit Clerk настроен как управляемая интеграция. Внешний VDS не получает production-ключи автоматически от Replit. Их нужно безопасно добавить в `.env` на VDS и настроить допустимый домен у провайдера Clerk. Не помещайте `CLERK_SECRET_KEY` в Docker build arguments, клиентский JavaScript, Git или публичные логи.

Проверки после запуска:

- `docker compose ps` — три сервиса работают и проходят healthcheck.
- Главная сайта отвечает по HTTPS на указанном домене.
- `/api/healthz` отвечает JSON со статусом `ok`.
- регистрация/вход Clerk, публикация объявления и прямая загрузка фото проверены на production bucket.
- в админке задан правильный адрес сайта; проверены `robots.txt`, `sitemap.xml` и canonical-ссылки.

Эта инструкция подготавливает конфигурацию и код. Она не создаёт VDS, кластер базы, bucket, DNS-записи, Clerk-настройки и не переносит данные.
