# Размещение ALL-YACHTS.RU на Deploy-F

## Выбор типа приложения

Для текущей архитектуры используйте **Docker Compose**: сайт, API и Caddy — отдельные сервисы. PostgreSQL размещается как отдельная база Deploy-F, фотографии — в S3-хранилище.

Обычная загрузка ZIP в Node.js здесь не подходит: корневой `pnpm run build` запускает сборку всего workspace, а сайту и API нужны разные процессы.

## Ограничения Compose на Deploy-F

Проверка в панели Deploy-F показала, что Compose-мастер:

- не собирает `build` из исходников; нужны заранее опубликованные образы;
- не читает `.env`;
- запрещает bind-mount файлов;
- не поддерживает `profiles`;
- не принимает публикацию одного порта 443 одновременно по TCP и UDP.

Поэтому для Deploy-F подготовлен отдельный `compose.deploy-f.yaml`. Исходный `compose.yaml` и `Caddyfile` для VDS оставлены без изменений.

## Опубликовать образы

Текущий Replit-токен может отправлять код в репозиторий, но не управляет видимостью GHCR-пакетов. Workflow GitHub Actions использует собственный `GITHUB_TOKEN` с разрешением загрузки образов.

Workflow запускается при обновлении ветки `deploy-f` и загружает три образа в GHCR:

- `ghcr.io/vlad-sem-77/all-yachts-site:deploy-f` — сайт и API;
- `ghcr.io/vlad-sem-77/all-yachts-site-migrate:deploy-f` — одноразовые миграции;
- `ghcr.io/vlad-sem-77/all-yachts-site-proxy:deploy-f` — Caddy с конфигурацией, встроенной в образ.

Новые GHCR-пакеты по умолчанию закрыты. Чтобы Deploy-F мог скачать образы без авторизации, один раз откройте [Packages в GitHub](https://github.com/Vlad-Sem-77?tab=packages), зайдите в настройки каждого из трёх пакетов выше и выберите **Change visibility → Public**. Текущий токен не имеет доступа к управлению видимостью; это не влияет на сборку и загрузку образов.

Переменная репозитория `CLERK_PUBLISHABLE_KEY` содержит публичный ключ, который встраивается в клиентский bundle. Секретный ключ Clerk, пароль администратора, адрес базы и ключи S3 в образы не записываются.

## Создать архив настроек

После публикации образов выполните:

```sh
bash scripts/package-deploy-f.sh
```

Создаются два архива:

- `generated-artifacts/all-yachts-deploy-f-compose.zip` — основной стек;
- `generated-artifacts/all-yachts-deploy-f-migration.zip` — отдельный запуск миграций.

Внутри каждого архива Compose-файл находится в корне и называется `compose.yaml`, как ожидает мастер. В основном архиве только Compose-файл и инструкция; исходный код не нужен, потому что сервисы используют опубликованные образы.

## Настройки в Deploy-F

Загрузите основной ZIP как Docker Compose. В панели Deploy-F задайте переменные для Compose-приложения; `.env` не используется:

- `DATABASE_URL` — подключение к PostgreSQL;
- `SITE_HOST` и `SITE_URL` — домен без схемы и URL с `https://` соответственно;
- `SESSION_SECRET`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`;
- `CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`;
- `S3_ENDPOINT_URL`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`;
- при необходимости `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`.

Пустые значения по умолчанию нужны только для прохождения проверки Compose. Заполните обязательные переменные до запуска сервисов. Caddy принимает трафик по TCP-портам 80 и 443; конфигурация уже включена в proxy-образ, поэтому mount файла не нужен.

## Миграции базы

Основной стек не запускает миграции автоматически. После создания новой пустой базы загрузите второй архив как отдельный Compose-проект, задайте ему `DATABASE_URL` и выполните одноразовый сервис `migrate`. После успешного завершения удалите проект миграции.

Не запускайте миграции на базе с важными данными без проверенной резервной копии и плана переноса.
