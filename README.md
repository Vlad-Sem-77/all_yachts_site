# Лодки, катера, яхты

SSR-доска объявлений на Express, EJS и PostgreSQL с Drizzle ORM. Основной веб-сервис находится в `artifacts/board`.

## Запуск в Replit

1. Установите зависимости: `pnpm install`.
2. Проверьте, что Replit PostgreSQL и Object Storage подключены к проекту.
3. В Secrets добавьте `ADMIN_USERNAME` и `ADMIN_PASSWORD`, чтобы открыть `/admin`. `SESSION_SECRET` также обязателен для сессии; в текущем Repl он уже настроен.
4. Запустите workflow `artifacts/board: web` (команда: `pnpm --filter @workspace/board run dev`).
5. Для локальной разработки с новой схемой БД примените **только к development-базе**: `pnpm --filter @workspace/db run push`. Команда не должна запускаться против production без отдельного плана миграции.

В `/admin/settings` задаются основной адрес сайта, аналитика, уведомления, валюты, страны и текст правил. Основной адрес нужен для абсолютных canonical-ссылок, sitemap и писем. Если задан Secret `SITE_URL`, он имеет приоритет над адресом из админки.

## Администрирование и резервная копия

- Админ-панель: `/admin`; доступ по `ADMIN_USERNAME` и `ADMIN_PASSWORD` из Secrets.
- Выгрузка БД доступна из админки как JSON. Она содержит контактные данные объявлений, хеши паролей авторов и системные таблицы — храните файл в защищённом месте.
- Выгрузка содержит данные базы, но не байты изображений из Object Storage. Для восстановления фотографий отдельно сохраните соответствующие объекты.
- Действие «Удалить» скрывает объявление и помечает его удалённым; восстановление через админку не предусмотрено.

## Почта и автоматическое истечение

Активные объявления автоматически скрываются после даты окончания (60 дней от размещения или продления). Раз в 15 минут работающий веб-процесс проверяет сроки и отправляет напоминание за три дня до окончания, если указан email автора.

Почтовые уведомления включаются при наличии SMTP-сервера. Добавьте в Replit Secrets:

- `SMTP_HOST`
- `SMTP_PORT` (например, `587` или `465`)
- `SMTP_USER`
- `SMTP_PASS`
- `SMTP_FROM` (адрес отправителя, разрешённый вашим SMTP-сервисом)

Тогда уведомления смогут отправляться на email для новых объявлений и жалоб, указанный в `/admin/settings`, а также авторам перед истечением срока. Без SMTP письма не отправляются; функции не имитируют успешную доставку. Сброс пароля автора по email пока отключён.

## SEO и аналитика

- `/robots.txt` и `/sitemap.xml` генерируются сервером по активным категориям и объявлениям.
- В HTML выводятся canonical, Open Graph, Product/Offer и хлебные крошки schema.org.
- Скрытые, удалённые и истёкшие объявления не попадают в sitemap; для истёкших и удалённых адресов возвращается `410` и `noindex`.
- Счётчики Google Analytics и Яндекс.Метрики не загружаются до согласия на аналитические cookie. ID настраиваются в `/admin/settings`.

## Публикация и собственный домен

Публикацию и подключение домена выполняйте после проверки Secrets и настроек админки. В Replit откройте Publishing и опубликуйте приложение. Затем в разделе Domains подключите домен, которым вы владеете, и внесите выданные Replit DNS-записи (A и TXT) у регистратора домена. После подключения укажите итоговый корневой `https://`-адрес в `/admin/settings` и проверьте canonical, sitemap и почтовые ссылки.

Подробности: [публикация приложения](https://docs.replit.com/build/publish-your-app), [подключение собственного домена](https://docs.replit.com/features/publishing/custom-domains).

## Размещение на внешнем VDS

Для Docker Compose, PostgreSQL и S3-хранилища см. [инструкцию по подготовке VDS](docs/vds-deployment.md). Конфигурация использует основной сайт и API-сервис, отдельную managed PostgreSQL и S3-совместимое хранилище; она не заказывает ресурсы и не переносит данные автоматически.
